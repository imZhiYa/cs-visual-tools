OPENJDK 心智源码HashMap.hash()—
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

① 从 key 到桶索引

HashMap 用高 16 位异或低 16 位做扰动，再用 hash & (n - 1) 定位。

先预测：为什么不是长度一到 8 就树化？

复杂度直觉

链表：顺序比较，最坏 O(n)。红黑树：利用排序关系，查找约 O(log n)。树化不是让 HashMap 变成 TreeMap：顺序仍由桶和节点结构决定。

退树化：UNTREEIFY_THRESHOLD = 6 主要用于 resize() 拆分树桶：拆分后的低位或高位链表节点数 ≤ 6 时，该侧退化为普通 Node 链表。普通 remove() 删除一个节点，不应仅因数量下降就直接退树化。

HashMap 不保证什么？

不保证遍历顺序；不保证线程安全；key 必须正确实现 hashCode() 与 equals()。允许一个 null key 和多个 null value。

主线迁移

需要 key 排序 → TreeMap
需要插入/访问顺序 → LinkedHashMap
需要并发读写 → ConcurrentHashMap
